# Contributing to CyberScience Thesis Template

Thank you for your interest in contributing to the **CyberScience Thesis Template** project! To maintain a high-quality codebase and ensure smooth collaboration, we follow the [Git Flow](https://danielkummer.github.io/git-flow-cheatsheet/) branching model and have established guidelines for pull requests and releases.

---

## Branching Model (Git Flow)

We strictly adhere to the Git Flow workflow:

- **`master` branch**
  Represents the currently stable and officially released thesis template.

- **Tags**
  Mark specific released versions, representing past stable states of the template.

- **`development` branch**
  Used as an integration branch where all new features and fixes are merged and tested before being released.

---

## Pull Request Process

To contribute changes, please follow these rules:

- **Update `CHANGELOG.md`**
  Every contributor must update the `CHANGELOG.md` file to document their changes before creating a merge request.

- **Use GitLab Merge Requests**
  All contributions must be submitted via GitLab [Merge Requests](https://docs.gitlab.com/ee/user/project/merge_requests/). This ensures proper code review and discussion.

- **Roles in Merge Requests:**
  - **Assignee:** The contributor who created the merge request.
  - **Reviewer:** One of the project maintainers listed in `MAINTAINERS.md`. They will review and approve the changes.

---

## Release Process

Releases are managed carefully to ensure stability and versioning consistency:

- **Only project maintainers** are authorized to create releases.

- Releases must follow [Semantic Versioning (SemVer)](https://semver.org/) guidelines for tagging, e.g., `1.0.0`, `1.2.3`.

---

## Additional Notes

- Write clear, descriptive commit messages.

- If you have any questions or need assistance, feel free to open an issue or contact one of the maintainers.

---

Thank you for helping improve the CyberScience Thesis Template! Your contributions are highly appreciated.
